# Meiti Admin System

**门店管理系统 · 面向零售门店的排班与人事管理前端**


</div>

## 项目简介

Meiti Admin System 是一个纯前端的门店后台系统，把纸质排班表和口头请假流程搬到浏览器里。系统覆盖员工档案管理、按周排班、请假审批、经营统计与操作日志，并按管理员、店长、员工三种角色划分可见范围，界面支持中英文实时切换。

项目不依赖任何后端服务，业务数据存放在浏览器 localStorage 中，每次改动即时持久化，刷新页面不丢失。执行 `npm run build` 后，构建脚本会把 JS 与 CSS 全部内联进 `dist/index.html`，产出单个 HTML 文件，双击即可在浏览器中运行，方便演示、拷贝和分发。

## 功能模块

### 员工管理

员工列表支持按姓名或补零工号实时搜索，并按部门、岗位下拉筛选，每页展示 8 条。新增与编辑共用一张表单，包含手机号格式校验。详情页把个人信息、入职信息与紧急联系人分区展示，其中工资字段仅对管理员渲染。工号由系统自动分配并递增，删除员工后该工号不会再被复用，因此历史日志不会指向错误的人。

### 排班管理

排班分两个视图。个人排班按员工逐日安排早班、午班、晚班，点选格子后按 Assign 提交；全店总览以「班次 × 星期」的矩阵展示所有人，格子内显示人数角标和最多若干个姓名，超出部分折叠为 `+N more`，点击格子弹出完整名单。

排班有两条硬性约束：一名员工同一天最多一个班次，改动已占用的日期会弹出确认框而不是静默覆盖；已批准请假的日期不允许排班。当前周的排班表可导出为 CSV，文件带 UTF-8 BOM，用 Excel 打开中文不乱码。

### 请假管理

员工在个人门户提交申请，记录初始状态为 `pending`，管理员同意或拒绝后才生效。每日请假额度分两级：常规上限 3 人，超过时弹出特批确认，绝对上限 5 人，任何情况下都不会被突破。为请假日排班时，系统会提示并询问是否清除该班次。

### 统计与日志

统计页的数字全部由当前员工、排班、请假数组实时计算，不做二次存储，因此不会出现数据过期。部门分布用 `conic-gradient` 绘制的饼图呈现，每日排班量用等宽柱状图呈现，两者均为纯 CSS 实现，没有引入图表库。

操作日志记录每一次变更的操作人、时间、动作与明细，仅管理员可见。删除员工时，其未来的排班与请假记录一并清除，历史日志保持原样。

### 双语界面

所有可见文案存放在 `en` 与 `zh` 两本字典中，组件通过 `t(key)` 取词。中文字典声明为 `Record<keyof typeof en, string>`，缺少任何一个键都会在编译期报错，两种语言的键集合无法漂移。语言选择写入 localStorage，登录页就已提供切换按钮。

## 角色与权限

登录不设密码，工号首字母即角色：`A` 为管理员，`B` 为店长，`C` 加数字为员工。

| 能力 | 管理员 `A001` | 店长 `B001` | 员工 `C001…` |
|---|:---:|:---:|:---:|
| 员工增删改 | 可 | 只读 | 无入口 |
| 查看工资 | 可 | 不可见 | 不可见 |
| 排班编辑 | 可 | 只读 | 无入口 |
| 请假审批 | 可 | 只读 | 仅本人申请 |
| 统计报表 | 可 | 可 | 无入口 |
| 操作日志 | 可 | 无入口 | 无入口 |
| 个人门户 | 可 | 可 | 可 |

店长的只读属性在渲染层实现：编辑控件不为其渲染，操作日志菜单项直接从导航中过滤掉。

## 技术栈

| 环节 | 选型 | 说明 |
|---|---|---|
| 界面框架 | React 19 | 函数组件 + Hooks，单向数据流 |
| 语言 | TypeScript 5.9 | 全量类型标注，业务模型集中在 `types/index.ts` |
| 构建 | Vite 7 | 开发服务器端口 3000，构建后由脚本内联为单文件 |
| 样式 | Tailwind CSS 3.4 | 主色 `#00C9A7`，深色栏 `#1B1B27 → #2D2D45` |
| 基础组件 | Radix UI + shadcn 风格封装 | `src/components/ui` 下 50 余个可复用组件 |
| 图标 | Lucide React | 与 shadcn 生态一致 |
| 表单 | 受控组件 + useState | 提交时逐字段校验，错误显示在对应字段下方 |
| 图表 | 纯 CSS | 无图表库依赖 |
| 持久化 | localStorage | 键前缀 `meiti2:`，数据切片分别存取 |

## 快速开始

环境要求：Node.js 18 或更高版本。

```bash
# 安装依赖
npm install

# 启动开发服务器（http://localhost:3000）
npm run dev
```

生产构建：

```bash
npm run build
```

该命令依次执行 `tsc -b`、`vite build` 与 `node scripts/inline-dist.mjs`，最终在 `dist/index.html` 得到单文件产物，控制台会打印产物体积。由于内联了全部脚本与样式，产物可以直接通过 `file://` 打开，浏览器的模块加载限制不会生效。

其他命令：

```bash
npm run preview   # 本地预览生产构建
npm run lint      # 运行 ESLint
```

## 设计取舍

**状态集中在一处。** 所有业务数据与规则都在 `App.tsx`，页面组件只接收 props 并回调。好处是排班冲突、请假额度、级联删除这类跨页面规则不需要重复实现；代价是 `App.tsx` 体积偏大，若继续扩展应拆分为若干自定义 Hook。

**危险操作一律弹窗确认。** 覆盖已有班次、超出请假额度、删除员工等动作都不会静默执行，而是把待执行的动作存进 `ModalState`，用户确认后才真正写入数据。

**不做路由库。** 页面切换用一个联合类型 `Page` 表示，每个页面携带自己需要的参数（例如 `detail` 必然带 `id`），TypeScript 会强制处理完整的分支。项目规模下引入 react-router 收益不大。

**数据层可替换。** localStorage 的读写被收敛在 `App.tsx` 的 load / save 函数中，接入真实后端时只需改写这两处，类型定义与页面逻辑不用动。

**已知限制。** 数据只存在当前浏览器，换设备或清缓存即丢失；没有密码校验，工号可见即可登录；并发多端编辑不会合并。这三点都源于课程作业的前端定位，接入后端后可以逐项解决。
